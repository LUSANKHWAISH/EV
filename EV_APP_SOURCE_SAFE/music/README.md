# Music foundation

Open E.V. normally and select **Music** in the header, or the music-note button in the left rail on a narrow window.

- **Open tracks** accepts local MP3, WAV, FLAC, AAC/M4A, Ogg/Opus, AIFF and WMA candidates. Actual decoding depends on Qt/FFmpeg. You can also drop files onto the Music page. Selecting files adds them to the session queue and plays the first newly added track.
- **E.V. player** visualizes that player's decoded PCM. Play/pause, stop, previous/next, seek, mute, volume and playback-output selection are available. Volume is remembered; the initial queue is session-only.
- **Windows audio** captures the chosen rendering endpoint using WASAPI loopback. Start music in VLC or a browser normally, then select this input. Other sounds on the same device are part of that mix. Stop capture releases the device. Capture is not a microphone and is never played back or saved.
- **Interface settings → Music reaction** offers Music only / All modes / Off and a saved 0–100% intensity slider. All modes is the default for this update. It keeps the selected source's analysis running when returning to Assistant; Windows capture stays on the same session. Music only releases capture and suspends analysis outside Music. Off disables core reactions but leaves the Music workspace's spectrum available. Local playback can continue in all three settings.
- In Music, the small core responds to detected attacks with sharp golden hub/glint pulses and up to 2.5% rigid expansion. In Assistant, it uses one-quarter of the selected intensity (maximum 0.625% expansion). Both player PCM and Windows audio drive the same detector. Silence, pause, mute and stale audio clear the pulses. Voice activity, speaking, active task lifecycle, approval and non-idle visual states take priority. Existing pause-animation settings stop the core's music response.
- Windows audio can also be selected in Interface settings. A visible **Windows audio · Active** indicator appears above telemetry outside Music and opens those settings. Stop capture remains stopped across mode changes until explicitly connected again. Device and capture state are session-only; selecting All modes does not start capture at app launch.

This is the first working player/capture milestone from the roadmap, not the completed music product. It includes one spectrum/waveform view and a simple local queue. Persistent library/playlists, cloud-provider clients, EQ/crossfade, tempo estimation and beat-grid tracking, external metadata/transport and the full preset gallery remain later work.

The display uses a 2048-sample Hann FFT with 64 logarithmic bands, plus RMS, sample peak and bass/mid/high energy. Measurements from the E.V. decode tap are adjusted by E.V.'s output volume/mute, but are not measurements after the Windows master volume. Output loopback reflects the selected Windows mix. Attack/release smoothing is presentation-only. The Qt backend produced 4096-frame buffers in the tested 48 kHz WAV case (approximately 85 ms); precise audible-to-visual latency has not been calibrated.

Beat response uses spectral onset detection over the whole incoming buffer: 1024-sample windows, 512-sample hops, an adaptive spectral-flux threshold, a silence gate and a 145 ms retrigger guard. Each detected attack triggers an immediate visual envelope with a 115 ms release. Sustained tones do not generate repeating pulses. This detects audio transients rather than predicting a BPM grid; dense mixes and non-musical Windows sounds can also trigger it. Player events are scheduled within their decoded buffer to avoid collapsing multiple attacks into one update.

No audio is captured or analyzed at ordinary app startup without an active source. Selecting Windows audio starts the visible capture session when Music is open or All modes is enabled. Music only temporarily suspends that session when leaving Music; manually stopping capture prevents automatic resumption. Capture devices can disappear or expose silence depending on routing/driver behavior; reconnect or choose the correct output. This Windows 10 build uses endpoint capture, not isolation of one application. Changes of physical device and exclusive/protected audio need additional hardware-specific testing.

Dependencies: PySide6 6.8+ with its FFmpeg backend, NumPy, and PyAudioWPatch 0.2.12.8 on Windows. The player has no dependency on `core/tts.py` or ASR. Runtime settings use QSettings `EV/MusicFoundation`.

Validation helpers use only a generated audio fixture. They do not require a user's music, cloud account or live executor. External validation launches its own bounded VLC process and isolated headless Chrome profile, then closes those test processes.
